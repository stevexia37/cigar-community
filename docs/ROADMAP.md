## 二、下一步（按性价比排序）

### P0 —— 上线前必须有

**1. 管理后台（审核队列界面）**
- 为什么：现在命中审核词的内容以 `reviews.status = -1` 入库，但**没有任何界面能看到它们**。
  没有这个界面，「审核队列」实际等于内容黑洞 —— 用户以为发出去了，运营根本看不到。
- 做什么：管理员登录 → 列出 `status = -1` 的笔记与 `submissions.status = 'pending'` 的投稿 →
  通过 / 驳回（填 `reject_reason`）→ 记录 `reviewed_by` / `reviewed_at`
- 后端地基已经在：`audit_log` 表、`requireAdmin` 守卫、`status` 三态都就绪
- 工作量：1 个后端路由模块 + 1 个前端页面

**2. 真正的 Secret 与管理员口令**
- `CC_SECRET` 生成：`node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`
- `CC_ADMIN_PASSWORD` 不要用默认值（生产模式会拒绝启动，这是刻意的）

### P1 —— 影响体验

**3. 图片上传**
- `review_images` 表已建但无上传接口，笔记目前只能发文字，而**雪茄笔记的价值一半在图**
- 建议：本地磁盘存 `uploads/` + `sharp` 压缩，或直接接对象存储（S3/R2）
- **必须同时做图片审核**（`config/sensitive-words.json` 的 `image_moderation` 已列建议：
  检测二维码、涉烟广告图 → 进人工审核）

**4. 中文分词搜索**
- 现状是 `LIKE '%关键词%'`，数据量小时够用；上万条后性能与召回都会退化
- 选项：SQLite 的 `FTS5` + `simple` 分词器（需编译扩展）、或迁 MySQL 用 `ngram`、或接外部搜索
- 触发条件：雪茄数据 > 5000 条，或搜索 P95 > 300ms

**5. 前端测试**
- 后端有 131 项断言，前端目前靠人工验证
- 建议：Playwright 覆盖 5 条主路径（年龄门 → 筛选 → 详情 → 登录 → 发笔记）

### P2 —— 规模化

**6. MySQL 迁移**：路径见 [ARCHITECTURE.md §七](ARCHITECTURE.md)
**7. 分布式限流**：内存限流多实例失效，需换 Redis
**8. CI/CD**：目前 `web/dist` 需手动构建，没有流水线、没有容器化
**9. 徽章系统**：`operations/badge-system.sql` 有设计稿，未接入代码

## 三、刻意不做（以及为什么）

| 不做 | 原因 |
|---|---|
| **在任何地方展示购买链接 / 价格交易功能** | 项目定位是「不卖茄，只聊干货」。一旦沾交易就是合规自杀，也是 `monetization/plan.md` 自己划的底线（只赚配件与 B2B 的钱） |
| **引入 Pinia / Vuex** | 全站只有一个共享状态（会话），`reactive` 足够。多一个依赖没有任何收益 |
| **引入 Express / Nest** | 见 [ARCHITECTURE.md §二](ARCHITECTURE.md) 的选型对比。零依赖的收益是确定的（clone 即跑），代价只有约 300 行自写原语 |
| **给 `database/schema.json` 接 Strapi** | 那份 JSON 是当初为 Strapi 准备的，但 Strapi 的定制成本远高于自写接口，且会和现有 `schema.sql` 形成第三份事实来源 |
| **保留 `cigar-filter/` 作为第二前端** | 两套前端的真实代价是**数据与逻辑必然分叉**（这次就是），已归档 |
| **把 `deployment/checklist.md` 全部自动化** | 它包含大量人工动作（KOL 投放、值守排班、DNS 割接），能自动化的部分（年龄门、敏感词口径）已经变成了断言 |

## 四、技术债清单

| 债务 | 影响 | 触发条件 |
|---|---|---|
| `LIKE` 搜索 | 数据量大后退化 | > 5000 条雪茄 |
| 内存限流 | 多实例失效 | 横向扩容时 |
| SQLite 单写入者 | 高并发写瓶颈 | 写入 QPS > 50 |
| 无管理后台 | 审核队列不可见 | 一上线就是问题，**建议优先** |
| 无 CI | 依赖人工跑测试 | 多人协作时 |
| `web/dist` 进构建产物但不进版本库 | 新机器需先 `npm run build` | — |
| 图片表存在但功能未实现 | 表结构空占位 | — |

## 五、给接手者的三个建议

1. **改接口先改 `docs/API.md`**。前端只依赖契约，不依赖实现。契约和代码不一致时，先修契约。
2. **加筛选/选项一律走 `/api/meta`**。前端不得出现任何硬编码的产地/型号/风味列表 —— 这是这次重构的核心成果，别退回去。
3. **改敏感词配置后必须跑 `npm test`**。`config/sensitive-words.json` 是数据而非代码，
   改动不会被类型检查拦住，只有那 15 项单元测试能告诉你是否引入了误杀。
